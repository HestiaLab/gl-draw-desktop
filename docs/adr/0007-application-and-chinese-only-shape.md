# ADR 0007：应用型项目与中文单语适配

## 状态

已接受。

**日期**：2026-10-23

## 背景

`c-project-standard` 的生成骨架围绕「核心库 + 可选示例可执行 + CMake 包导出」
设计。本项目是纯桌面绘图应用：没有稳定的库 API，也不需要被其他 CMake 项目
`find_package` 消费。同时，项目只提供中文界面与文档，并随包分发中文字体。

## 决策

1. **纯应用形态**：只构建 `gldrawdesktop` 可执行文件，不导出库、不安装公共头、
   不生成 CMake 包配置。安装内容为可执行文件、着色器、主题、脚本、字体与文档。
2. **最小新增公共 API**：`include/gldrawdesktop/app.h` 只暴露
   `gldrawdesktop_run()` 与 `gldrawdesktop_version()`；既有模块公共头保持原路径。
3. **中文单语**：界面、文档、命令行提示与提交摘要使用中文；不维护英文镜像。
   内部标识符、JSON 键、命令 ID 与提交类型保持英文。
4. **字体随包分发**：界面字体使用 Noto Sans SC Regular（OFL），按 GB2312 常用
   字范围烘焙图集，避免依赖系统字体差异。字体路径可通过
   `GLDRAWDESKTOP_FONT` 覆盖。
5. **模板基建对齐**：采用 `ninja-*` presets、bootstrap/check 脚本、Unity 测试、
   声明/定义、版本、文档、门禁自检与 CPack 配置门禁；不引入库包冒烟、
   subproject 冒烟与 MSI。

## 后果

- 下游无法通过 `find_package` 消费本项目；未来若需要库化，应新增 ADR 并重新
  引入导出目标与包冒烟测试。
- 仓库增加约 11MB 字体文件；启动时按 GB2312 范围烘焙图集，带来额外启动时间与
  显存占用。
- CI 的安装冒烟验证可执行文件、字体、许可证与文档，不验证库消费路径。
- 中文 UI 的窗口与字体渲染由人工冒烟验证，CTest 不覆盖 GUI。
