# AI 代理工作流

这些 playbook 定义常见 AI 辅助任务的默认流程。它们不替代 `AGENTS.md`、
`CONTRIBUTING.md` 或 ADR。

## 通用流程

1. 阅读 `AGENTS.md` 与任务 Issue。
2. 阅读 `CONTRIBUTING.md`、[AI 代理政策](ai-agents.md) 与
   [测试指南](testing.md)。
3. 编辑前检查最小相关文件集。
4. 说明或记录本次范围。
5. 做聚焦改动。
6. 运行相关本地检查。
7. 总结改动文件、验证结果与残余风险。

## 缺陷修复

1. 复现或定位失败行为。
2. 编辑前找到所属模块。
3. 尽量补充回归测试。
4. 只修复拥有该缺陷的最小行为面。
5. 先运行聚焦测试，再按风险运行更广的 preset。
6. 记录仍需人工验证的部分。

## 功能开发

1. 确认目标、非目标与受影响工作流。
2. 判断功能属于 document、command、tool、workspace、UI、render 还是 platform。
3. 持久文档变更通过命令实现。
4. UI 保持薄且以 action 为中心。
5. 为行为与状态转换补充测试。
6. 行为变化时更新操作、构建、发布或用户文档。

## CI 或构建修复

1. 检查失败任务、日志与工作流。
2. 尽量用对应 preset 或脚本在本地复现。
3. 修复项目根因，而不是掩盖检查。
4. 工作流改动与 `CMakePresets.json` 和 `scripts/check.*` 保持一致。
5. 运行 `cmake --list-presets`、`ctest --list-presets` 与受影响门禁。

## 代码评审

1. 阅读 PR diff 与相关源码上下文。
2. 优先关注正确性、回归、所有权边界与缺失测试。
3. 用文件路径与行号引用发现。
4. 除非违反共享规则，否则避免纯风格意见。
5. 区分已确认问题与风险/疑问。

## 重构

1. 明确必须保持不变的行为。
2. 找到所有权边界，非必要不做跨模块重塑。
3. 优先小步机械改动，并保持测试通过。
4. 不要把重构与功能行为混在同一改动中。
5. 运行覆盖所有触及模块的测试。

## 发布与打包

1. 阅读 [发布流程](release.md) 与 [CMake 指南](cmake.md)。
2. 除非任务明确要求，否则保持既有制品名称与安装布局。
3. 尽量在本地或 GitHub Actions 运行 Release Smoke。
4. 用户可见改动同步更新 `CHANGELOG.md`。
5. 未经维护者明确指示，不要发布标签或 Release。
