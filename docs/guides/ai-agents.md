# AI 代理政策

AI 代理可以参与项目开发，但其产出与其他贡献一样受架构边界、检查与人工评审
约束。

## 必读

修改文件之前，AI 代理应阅读：

- `AGENTS.md`
- `CONTRIBUTING.md`
- [测试与质量门禁](testing.md)
- 本文件

涉及架构的改动，还需阅读 [架构决策记录](../adr/README.md) 与相关 ADR。
涉及发布、打包、CI 或依赖的改动，还需阅读
[CMake 与构建](cmake.md)、[发布流程](release.md)、
[依赖与第三方源码](dependencies.md) 与 `SECURITY.md`。

## 适用场景

AI 代理适合：

- 有明确复现步骤的聚焦缺陷修复。
- 有验收标准的中小型实现任务。
- 测试补充与回归覆盖。
- 文档、构建、CI、打包与仓库维护。
- 保持行为的机械重构。
- 初审或风险分析。

## 受限场景

AI 代理不得独立：

- 在没有 ADR 或维护者指示时重设计核心架构。
- 未经明确评审改变文档文件格式兼容性。
- 绕过 `CommandExecutor` 直接修改持久文档。
- 把编辑规则搬进 UI 控件。
- 在 workspace 实现或生命周期测试之外新增 `workspace_internal.h` 依赖。
- 为让改动通过而削弱测试、CI、静态分析、安全检查或发布验证。
- 未经维护者批准引入生成代码、大型 vendored 依赖或许可证敏感资源。
- 发布 Release、轮换凭证或修改仓库权限。

## 人工评审

所有 AI 辅助 PR 都需要人工评审。评审者应检查：

- 代理是否阅读并遵循必读上下文。
- 改动是否限定在任务范围内。
- 架构边界是否保持。
- 测试是否覆盖真实行为。
- 生成文本、代码或资源是否许可证安全。
- 是否仍需手动 UI、渲染或打包验证。

## 披露与可追溯性

PR 模板中的 AI 辅助章节应写明工具、完成的工作、已读文档与人工验证结果。
适合代理的 Issue 使用 AI 任务模板，定义背景、目标、非目标、必读上下文、
预期文件、验收标准与必需检查。
